## The flaky test (`b7bfe55`)

`completion versus close (P2)` set `closesAt` 300 ms after the database clock and then called `beginDispatch`. On a cold Postgres with the other pg test file running, setup took longer than 300 ms, so `beginDispatch` saw the epoch closed and returned `not_ready`. A 400 ms delay before `beginDispatch` reproduced it every time. The test now keeps the epoch open until the dispatch exists, then sets the 300 ms boundary. `completeDispatch` reads `closesAt` when it accepts, so the race still tests the same rule. Test-only change; it passed with the delay in and on repeated runs without it.

## Runbook corrections (use these next time)

- **Deploy from the repo root, not `apps/api`.** The Dockerfile copies the lockfile and `packages/` from the root, and Fly uses the directory you deploy from as the build context: `fly deploy . --config apps/api/fly.toml --dockerfile apps/api/Dockerfile --app hyphae-api`.
- **If the build hangs at "Waiting for depot builder…"**, stop it and add `--depot=false` (Fly's legacy remote builder). That is what built this image.
- **Neon migrations run from Cisco's terminal:** `node --env-file=..\..\.env node_modules\drizzle-kit\bin.cjs migrate` from `packages/db`. The agent's auto-mode classifier refuses it as a production change.
- **Scripts need the full app env.** `set-rubric.ts` imports `src/db.ts`, which parses every required variable, so the local `.env` needs `LINK_ORIGIN` too (added). A failed parse stops before any connection.
- Read-only checks from the agent side work with `node --env-file=.env` and a `begin("read only")` transaction.
