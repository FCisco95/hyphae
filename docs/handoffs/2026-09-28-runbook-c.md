# Runbook C — mainnet setup and the first payout (Oct 7–9)

## How to run it

- **Every step is a hard stop.** Cisco says yes before it runs and the agent checks it before the next one, **one step per message**, as in Runbook B (`2026-09-24-cutover-decisions.md`).
- **Cisco runs** every Fly, Vercel and Neon-write command, in his own PowerShell from the repo root, and approves every Ledger prompt.
- **The agent runs** the read-only checks, the builds, the hot deploy key and the Solana CLI commands the Ledger signs. Cisco's hands are needed only on the device.
- **Secrets never pass through a paste into PowerShell.** They are read from the gitignored `.env`, which Cisco edits in an editor, as in Runbook B step 9.
- **No step is skipped or reordered.** A failed check stops the runbook there.

**Fixed values** (from `2026-09-27-keys-and-fee-rulings.md`):

|---|---|
| Program | `EAz8WkyUbGqr3ewSLpk94GWEoiWsvMENE5zV7Tvh4d6E` (keypair `target\deploy\hyphae-keypair.json` on the Windows machine; offline copy on Cisco's SSD) |
| Admin and upgrade key | `2kz1Zq8UDm9Hq6XwPW6cViQZe7aySEBGk1gLWN8gofjR`: Ledger `44'/501'/2'/0'`. Hyphae's scripts take `--signer ledger:44'/501'/2'/0'`; the Solana CLI takes `usb://ledger?key=2/0`. |
| MYCEL's fee address | The MYCEL Treasury vault, `rRceAUBNsnZKJDytjdHfCdqgTJGoDagtKujfvaBu7MK`. **Never** the multisig account `34wSn95ZFMsvsq7w6g8Rej7GSagGmpc6Vq5aHiCebu51`. |
| Verified build | `hyphae.so` sha256 `cb4ffdd8…8d79`; on-chain hash (`solana-verify`) `7e902d1b5f8d8c49dfd199ec2e7bf44139b56524d98408f1556e14f4e9ab43ac` (`2026-09-28-verifiable-build-and-deploy-rehearsal.md`) |
| Pot | 0.5 SOL = 500,000,000 lamports (P2) |
| First paid epoch | Epoch 2, closes 2026-10-09T00:00:00Z (`first_paid_epoch = 2` is the Oct 1 checklist's last step) |

**The Ledger, every time it is used:**
1. Firmware and the Solana app up to date; in the app's settings, **Blind signing on**.
2. **Ledger Live quit**: it holds the USB device.
3. Connected to the Windows machine, unlocked, with the Solana app open.

With blind signing, the device shows a hash, not the instruction. What Cisco checks is the plan the command prints before it asks.

**The Solana CLI for the Ledger.** WSL can't see the USB device, so every Ledger-signed CLI command runs from Agave's Windows build of the same version, v3.1.10 (`solana-release-x86_64-pc-windows-msvc.tar.bz2`, sha256 `84abbbf2…c06b`). The agent unpacks it to `%USERPROFILE%\solana-3.1.10` in C8 and calls it as `solana.exe` below. The mainnet RPC is `READ_RPC_URL` from `.env`, written `<rpc>` below.

**Budget** (mainnet rent read 2026-09-28; the rate is 5,080 lamports a byte, including the 128-byte account header):
- **Hot deploy key:** 1.2 SOL. The buffer's rent, 1.1663934 SOL, becomes the program's; add 0.00083312 SOL for the program account and about 0.002 SOL in fees for about 230 transactions. The rest is swept back.
- **Admin `2kz1Zq…`:** 0.02 SOL. The community and vault rent is 0.00192532 SOL, the epoch account's 0.00142748 SOL, plus fees.
- **Pot:** 0.5 SOL into the vault.
- **Claimant:** about 0.002 SOL of their own, for the receipt's rent (0.0013 SOL) and the fee.

## Part 1 — the payout candidate on Fly and Vercel (Oct 7)

Preconditions:
- The Oct 1 checklist in `docs/HANDOFF.md` is done: 0009 applied, `86ff258` deployed, the Vercel project live, `first_paid_epoch = 2`.
- The candidate is the `main` commit named in the handoff at the time.

### C1. Gate the candidate (agent)
- **Run:** in a temporary worktree at the candidate: `pnpm -r test`, `pnpm -r typecheck`, Biome on tracked files, `drizzle-kit check`, `test:pg`, `git diff --check`.
- **Check:** all pass. Record the SHA.
- **Rollback:** none needed; nothing has changed.

### C2. Neon pre-check (agent, read-only)
- **Run:** inside `sql.begin("read only", …)`:
  - the journal holds exactly 0000–0009, with matching hashes;
  - 0010's columns, 0011's tables and 0012's `leaves_wallet` index are absent;
  - row counts of `reward_configs`, `reward_decisions`, `reward_intakes`, `reward_snapshot_entries` and `leaves`;
  - `pg_stat_activity` shows no transaction open longer than 5 s.
- **Check:** as listed.
- **Rollback:** none needed.

### C3. Stop the worker (Cisco)
- **Why:** 0010 takes ACCESS EXCLUSIVE on four reward tables. The worker is their main writer, through scoring, the recovery sweep and the close. The api only writes them on a `/submit`, in short transactions.
- **Run:** `fly machines list --app hyphae-api`, then `fly machine stop <worker machine id> --app hyphae-api`.
- **Check:** `fly machines list` shows the worker `stopped` and the api `started`; `/health` 200.
- **Rollback:** `fly machine start <worker machine id> --app hyphae-api`.

### C4. Apply 0010–0012 (Cisco)
- **Run:** from `packages\db`: `node --env-file=..\..\.env node_modules\drizzle-kit\bin.cjs migrate`. The agent reruns C2's activity check first.
- **Check:** `migrations applied successfully!`.
- **Rollback:** **no rollback**; migrations are never rolled back. They only add columns, checks, two tables and an index. The running `86ff258` image names its columns and ignores them, so it keeps working. If the migrator fails, it rolls back its transaction and nothing is applied; fix the cause, then run it again.

### C5. Neon post-check (agent, read-only)
- **Run:** the same reads as C2.
- **Check:**
  - the journal holds 0000–0012, with matching hashes;
  - the new columns, the two 0011 tables and `leaves_wallet` exist;
  - the row counts are unchanged, and every new hash column is still null;
  - `/health` 200.
- **Rollback:** as C4.

### C6. The read secrets (Cisco)
- **Run:**
  1. In an editor, add to `.env`: `READ_RPC_URL=<a mainnet https RPC>` and `READ_API_WEB_TOKEN=<at least 32 random characters>`, for example the output of `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`.
  2. Set both on Fly, staged, from `.env`:
     ```powershell
     $r = ((Get-Content .env | Select-String '^READ_RPC_URL=').Line -split '=', 2)[1].Trim()
     $w = ((Get-Content .env | Select-String '^READ_API_WEB_TOKEN=').Line -split '=', 2)[1].Trim()
     fly secrets set "READ_RPC_URL=$r" "READ_API_WEB_TOKEN=$w" --stage --app hyphae-api
     Remove-Variable r, w
     ```
  3. In the Vercel dashboard (Project → Settings → Environment Variables, Production), add `HYPHAE_API_TOKEN` with the **same** value as `READ_API_WEB_TOKEN`, copied from the `.env` file in the editor.
- **Check:** `fly secrets list --app hyphae-api` shows both as Staged; Vercel lists `HYPHAE_API_TOKEN`.
- **Rollback:** `fly secrets unset READ_RPC_URL READ_API_WEB_TOKEN --stage --app hyphae-api`; delete the Vercel variable.

### C7. Deploy the candidate (Cisco)
- **Run:** from the repo root, at the candidate commit: `fly deploy . --config apps/api/fly.toml --dockerfile apps/api/Dockerfile --app hyphae-api --depot=false`. Note the new image and the previous one. Then `fly machine start <worker machine id> --app hyphae-api` if the deploy left the worker stopped. Then redeploy the Vercel site so it reads `HYPHAE_API_TOKEN`.
- **Check (agent):**
  - `/health` 200;
  - `/v1/openapi.json` 200;
  - `/v1/communities/<MYCEL mint>` answers;
  - its epochs' `settlement.allocation` is `unavailable` with a reason (`before_first_paid_epoch` or `no_settlement`), never a guess;
  - `RateLimit-*` headers are present;
  - both secrets show Deployed;
  - the worker log's `consuming` line lists `hold-check`, `reward-recovery` and `reward-close`;
  - the site's home page loads through the token.
- **Rollback:** `fly deploy --config apps/api/fly.toml --app hyphae-api --image registry.fly.io/hyphae-api:<previous image>`. The schema stays: `86ff258` runs on 0010–0012, see C4.

## Part 2 — the program on mainnet (Oct 7–8)

### C8. Windows CLI and Ledger readiness (agent; Cisco's device)
- **Run:**
  - The agent unpacks the Windows CLI and checks it: sha256 `84abbbf2…c06b`, and `solana.exe --version` reads `3.1.10 (src:7bc9c805…)`.
  - `solana-keygen.exe pubkey target\deploy\hyphae-keypair.json` must print `EAz8WkyU…d6E`.
  - `solana.exe account EAz8WkyU…d6E -u <rpc>` must say `AccountNotFound`.
  - Cisco readies the Ledger. The agent runs `solana-keygen.exe pubkey usb://ledger?key=2/0`.
- **Check:** the last command prints `2kz1Zq8UDm9Hq6XwPW6cViQZe7aySEBGk1gLWN8gofjR`.
- **Ledger approvals:** 0 (reading an address signs nothing).
- **Rollback:** none needed.

### C9. Verifiable build (agent)
- **Run:** in WSL, from a fresh clone at the candidate: `cd programs/hyphae && anchor build --verifiable --ignore-keys`, then `solana-verify get-executable-hash ../../target/verifiable/hyphae.so`. Return to the clone's root for C11.
- **Check:** sha256 `cb4ffdd8…8d79` and hash `7e902d1b…43ac`. A different hash means the program changed after its review. **Stop** until that change has been reviewed.
- **Rollback:** none needed.

### C10. Hot deploy key (agent generates; Cisco funds)
- **Run:**
  - The agent: `solana-keygen new --no-bip39-passphrase -o ~/hyphae-mainnet/deploy-hot-<date>.json` and `…/deploy-buffer-<date>.json` in WSL, then prints the hot key's address.
  - Cisco sends it **1.2 SOL** from a wallet he chooses.
- **Check:** `solana balance <hot> -u <rpc>` reads 1.2 SOL.
- **Ledger approvals:** whatever Cisco's funding wallet asks, one transfer.
- **Rollback:** the hot key sends its balance back (C13).

### C11. Write the buffer, then hand it to the Ledger (agent, hot key)
- **Run:**
  1. `solana program write-buffer target/verifiable/hyphae.so --buffer deploy-buffer-<date>.json --keypair deploy-hot-<date>.json -u <rpc> --with-compute-unit-price <µlamports>`. Take the price from the RPC's priority-fee estimate on the day. If a write fails, rerun the same command: it resumes into the same buffer.
  2. `solana program set-buffer-authority <BUFFER> --new-buffer-authority 2kz1Zq8UDm9Hq6XwPW6cViQZe7aySEBGk1gLWN8gofjR --keypair deploy-hot-<date>.json -u <rpc>`
- **Check** (these reads are what Cisco approves C12 on):
  - `solana program show <BUFFER> -u <rpc>`: authority `2kz1Zq…`, data length 229,432;
  - `solana-verify get-buffer-hash -u <rpc> <BUFFER>` = `7e902d1b…43ac`.
- **Ledger approvals:** 0.
- **Rollback:**
  - Before 2: `solana program close <BUFFER> --keypair deploy-hot-<date>.json -u <rpc>` returns the rent to the hot key.
  - After 2: only the Ledger can close it, with the hot key paying the fee: `solana.exe program close <BUFFER> --authority "usb://ledger?key=2/0" --keypair <hot key file> --recipient <hot> -u <rpc>`, 1 approval.

### C12. Deploy, signed by the Ledger (agent runs; Cisco approves)
- **Run** on Windows, with the hot key as fee payer:
  ```powershell
  solana.exe program deploy --buffer <BUFFER> --program-id target\deploy\hyphae-keypair.json `
    --upgrade-authority "usb://ledger?key=2/0" --keypair <hot key file> -u <rpc> `
    --with-compute-unit-price <µlamports> --output json
  ```
  One transaction: create the program account, then `DeployWithMaxDataLen` (max length 229,432; later upgrades extend it automatically). Its signers are the hot key, the program keypair and the Ledger.
- **Check:** the command prints the signature.
- **Ledger approvals:** **1** (blind), for `2kz1Zq…` as upgrade authority.
- **If it fails:**
  - **Rejected on the device, or the device timed out before signing:** nothing was signed, so nothing can land. The buffer stays with the Ledger for a retry.
  - **Anything after the device signed** (a CLI error, an RPC timeout, a lost confirmation): the deploy may have landed and consumed the buffer. **Do not retry.** First run C13's three reads:
    - if the program exists with authority `2kz1Zq…` and hash `7e902d1b…43ac`, and the buffer is gone, it landed: continue with C13;
    - if the program does not exist and the buffer still holds the verified hash under `2kz1Zq…`, it did not land: retry C12;
    - anything else: stop and ask Cisco.
- **Rollback:** **no rollback** for a landed deploy. The Ledger alone can upgrade the program (a new reviewed build, same sequence) or close it.

### C13. Read the program back, then close the hot key (agent)
- **Run:**
  - `solana program show EAz8WkyU…d6E -u <rpc> --output json`;
  - `solana-verify get-program-hash -u <rpc> EAz8WkyU…d6E`;
  - `solana account <BUFFER> -u <rpc>`.
- **Check:**
  - **authority `2kz1Zq8UDm9Hq6XwPW6cViQZe7aySEBGk1gLWN8gofjR`**;
  - data length 229,432; **hash `7e902d1b…43ac`**;
  - the buffer is `AccountNotFound`.
  - Record the signatures and the ProgramData address in the build log.
- **Then close the hot key, in this order**, only after the checks pass:
  1. Send its balance to the address Cisco names: `solana transfer <address> ALL --keypair deploy-hot-<date>.json -u <rpc>`.
  2. Confirm that transfer's signature succeeded: `solana confirm -v <signature> -u <rpc>`.
  3. Read the hot key's balance back as 0.
  4. Only then delete `deploy-hot-<date>.json` and `deploy-buffer-<date>.json`. On any failure or doubt, keep both files and retry the sweep.
- **Ledger approvals:** 0.
- **Rollback:** if the authority or hash is wrong, **stop**; do not fund anything. Only the Ledger can then act on the program.

## Part 3 — MYCEL's community and its vault (Oct 8)

### C14. Fund the admin for fees and rent (Cisco)
- **Run:** send **0.02 SOL** to `2kz1Zq8UDm9Hq6XwPW6cViQZe7aySEBGk1gLWN8gofjR`.
- **Check:** `solana balance 2kz1Zq… -u <rpc>` (agent).
- **Ledger approvals:** one transfer from Cisco's funding wallet.
- **Rollback:** none needed; the balance is spent only on Hyphae's rent and fees.

### C15. Plan the community (agent; Cisco checks the output)
- **Run:** from `apps\api`, no `.env` needed:
  ```powershell
  node --import tsx scripts/init-community.ts plan --mint <MYCEL mint> `
    --fee-recipient rRceAUBNsnZKJDytjdHfCdqgTJGoDagtKujfvaBu7MK --network mainnet --rpc <rpc> `
    --signer "ledger:44'/501'/2'/0'" --gross 500000000
  ```
- **Check:** the output names:
  - program `EAz8WkyU…d6E` and admin `2kz1Zq…`;
  - the community and vault addresses (record them);
  - the fee recipient `rRceAUBN…u7MK` as a System-owned wallet. Cisco also compares it with the Squads app's Receive screen for the MYCEL Treasury.
  - The command refuses the multisig account `34wSn…` (it is owned by Squads) and any address with no account.
- **Ledger approvals:** 0 (the address is read, nothing is signed).
- **Rollback:** none needed.

### C16. Initialize the community (agent runs; Cisco approves)
- **Run:** the same command with `send` in place of `plan`. It simulates `initialize_community` before the device is asked, then reads the account back.
- **Check:**
  - it prints `initialized: <signature>`;
  - the read-back community names the MYCEL mint, admin `2kz1Zq…` and fee recipient `rRceAUBN…u7MK`;
  - it prints the `update communities set chain_address = …` line.
- **Ledger approvals:** **1** (blind), `initialize_community`.
- **Rollback:** **no rollback.** The community address and its fee recipient are permanent; the program has no instruction to change or close them. This is why C15's output is read before C16.

### C17. Bind the community in Neon (Cisco)
- **Run:** the printed statement, which only fills a null:
  `update communities set chain_address = '<community>' where mint = '<MYCEL mint>' and chain_address is null;`
- **Check (agent, read-only):** `select chain_address from communities where mint = '<MYCEL mint>'` equals C16's community.
- **Rollback:** before any publish, `update communities set chain_address = null where mint = '<MYCEL mint>';`. The publish script refuses a community whose address differs from the chain's.

### C18. Fund the vault for one epoch (Cisco approves)
- **Run:**
  1. Rerun C15's `plan … --gross 500000000`. It prints `send the vault <T> lamports`: the pot, less what the vault already holds beyond its rent and unclaimed allocations.
  2. The agent sends exactly that from the admin, once Cisco has moved T to it:
     ```powershell
     solana.exe transfer --from "usb://ledger?key=2/0" --fee-payer "usb://ledger?key=2/0" `
       <VAULT> <T in SOL> -u <rpc>
     ```
     Or Cisco sends T to the vault himself from the wallet he chooses: Question 2 in `2026-09-28-arc.md`.
- **Check:** the plan rerun says `a pot of 500000000 lamports (0.5 SOL) is covered`.
- **Ledger approvals:** **1**, a plain SOL transfer. The device shows the amount and the vault address; no blind signing.
- **Rollback:** **no rollback.** The program has no withdrawal: vault lamports leave only through claims of published epochs. Anything above the pot stays for later epochs.

### C18b. Epoch 2's entries, before it closes (agent reads; Cisco corrects) — by 2026-10-08, before 2026-10-09T00:00Z
- **Why now:** a correction made after the close is late and changes nothing allocated. Epoch 2 runs from Oct 2, mostly on the Oct 1 image `86ff258`, which lacks the fix for security-review finding HYP-01 (`747faa7`, deployed in C7): two replies sent at once to one raid could both be admitted.
- **Run (agent, read-only):**
  1. List any member with two first-entry contributions of one kind in one raid of epoch 2: contributions joined to their `reward_intakes`, `reentry_of is null`, grouped by member, task and kind, `having count(*) > 1`.
  2. If Cisco rules the handle attestation (Question 1 in `2026-09-28-arc.md`), list each scored member's bound X handles for him to confirm as their own.
- **Then (Cisco):** each duplicate, or each post from an account that is not the member's, is corrected with `scripts/reward-correct.ts` on his yes, before the close.
- **Check:** the list is rerun and empty, or every entry on it is corrected; either result is recorded.
- **Rollback:** a correction is an appended revision, and a later correction supersedes it; nothing is deleted.

## Part 4 — the first payout (Oct 9, after 2026-10-09T00:00Z)

Epoch 2 must be closed, and the worker's hold checks recorded (within 24 h of the close).

**Stop before C19** if C18b is not recorded as clean or fully corrected, or if a duplicate or a borrowed post comes to light after the close. A correction then changes nothing allocated (the frozen close keeps revision 1), so publishing that epoch needs Cisco's separate decision.


### C19. Plan the publication (Cisco)
- **Run:** from `apps\api`:
  ```powershell
  node --env-file=<abs .env> --import tsx scripts/publish-epoch.ts plan --mint <MYCEL mint> --epoch 2 `
    --gross 500000000 --network mainnet --rpc <rpc> --signer "ledger:44'/501'/2'/0'"
  ```
  It stores the publication intent in Neon (a production write), or prints the gate's blockers and stores nothing.
- **Check:** the printed plan:
  - gross 500,000,000, fee 15,000,000 (300 bps) to `rRceAUBN…u7MK`;
  - the allocated total and every leaf's wallet and amount;
  - the root and audit hash.
  - Blockers such as `hold_checks_pending` mean wait and rerun, never override.
- **Ledger approvals:** 0.
- **Rollback:** the intent is stored before any send, and a rerun records the same bytes. Nothing on-chain has changed.

### C20. Publish (Cisco runs; Cisco approves)
- **Run:** the same command with `publish`. It sends exactly the stored intent, simulated first.
- **Check:** `published: <signature>, root …, <n> leaves`.
- **Ledger approvals:** **1** (blind), `publish_epoch`. The operator checks C19's printed numbers, not the device's hash.
- **Rollback:** **no rollback.** The root is on-chain for good. A crash after the send is recovered by rerunning `publish`, which finds the landed transaction and records it.

### C21. One claim (a tester, with Cisco)
- **Run:** a paid tester opens `/claim` on the Vercel site, connects the wallet their `/link` verified, and signs. They need about 0.002 SOL of their own.
- **Check:** the page shows the claim transaction; the member reads `paid` on the epoch page.
- **Ledger approvals:** 0; the tester's wallet signs.
- **Rollback:** **no rollback.** The receipt stops a second claim of the same leaf.

### C22. The P14 read (agent, read-only)
- **Run:** `GET https://hyphae-api.fly.dev/v1/communities/<MYCEL mint>/epochs/2`, `GET /v1/wallets/<tester>/claims`, and the epoch page on the site.
- **Check:**
  - `settlement.allocation`: `published`, with `publish_tx` = C20's signature;
  - `settlement.payment`: `available`; the tester `paid` with `claim_tx` = C21's signature, and every other payable member `claimable`;
  - claimed and unclaimed sum to the allocated total;
  - the fee and the cap remainder match C19.
  - Record everything in `docs/BUILDLOG.md` and a dated snapshot.
- **Rollback:** none needed.
