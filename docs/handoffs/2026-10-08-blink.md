# Blink for the claim, 2026-10-08

Built by Claude Opus 5.5 as an Orca worker, branch `FCisco95/blink`. Local commits only (implementation `92ccd20`): nothing pushed, merged or deployed. Web only (`apps/web`): no API route, no migration, no config, no new dependency.

## What works

- **`GET /api/actions/claim/<mint>/<epoch>`** reads the epoch the way the epoch page does. A published epoch returns an Action: title `Claim · <community> · Epoch <n>`, the Hyphae mark as icon, a description of the payout, and one `transaction` action labelled "Claim". An epoch with nothing to claim returns the same Action with `disabled: true` and the epoch page's own sentence as the description. A malformed link answers 400, an unknown epoch 404, an unreadable API 503, each with an `ActionError` (`{ message }`).
- **`POST`** with `{ "account": "<wallet>" }` checks the wallet address (`isAddress`, body at most 1 KiB), reads the epoch, then the wallet's leaf through the existing claim read (the visitor's address goes to the API's rate limit, as on the claim page). A claimable leaf returns `{ type: "transaction", transaction: <base64>, message }`, built by `claimTransaction` in `apps/web/lib/claim.ts`, the function the claim page uses. Errors: no leaf 404, already claimed 409, not published 409, chain cannot confirm 503, a leaf the builder refuses 503 (logged, nothing built).
- **`OPTIONS`** on the Action and **`/actions.json`** answer with the spec's CORS headers. Every Action response carries `X-Action-Version: 2.4`. A response that knows the epoch's chain also carries `X-Blockchain-Ids` (CAIP-2: mainnet `solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp`, devnet `solana:EtWTRABZaYq6iMfeYKouRu166VU2xqa1`). Responses are `no-store`. The wildcard origin applies to these routes only.
- **`/actions.json`** maps `/c/*/e/*/claim` to `/api/actions/claim/*/*`, and the Action path to itself.
- **Share link:** the claim page and the receipt page (`/contribution/<id>`) show "Share claim link on X" when the epoch is published. It opens X's composer with the claim page URL on `https://hyphae-delta.vercel.app`. A blink-aware client shows that URL as the claim (through `actions.json`). Anywhere else it opens the claim page, which works today. The receipt page makes one more epoch read (cached 15 s); if that read fails, the link is left out.

**Safety.** The server signs nothing and holds no key. The web makes no RPC call: the blockhash comes from the API's existing claim read, as on the claim page. The transaction is the claim page's own: same function, same read, and a test checks the bytes are equal. Its only signer slot is the member's and it is empty; the member is the fee payer. Under the spec, a blink client sets its own fee payer (the same member) and a fresh blockhash before the wallet signs; the instructions do not change. The program still decides who may claim (it rebuilds the leaf from the signer). No custody change.

**Design choice.** The Action path is `/api/actions/claim/<mint>/<epoch>`, not `?mint=&epoch=`. Why: `actions.json` rules map page path segments onto API path segments. Mapping them into query parameters is not in the spec. The reference client (Dialect's `blinks-core` URL mapper) fills each `*` in order, and a test applies that rule.

## New member-visible strings (for Cisco's approval)

Web page:
- `Share claim link on X` (claim page and receipt page, published epochs only)

Blink card (GET):
- Title `Claim · <community> · Epoch <n>`
- Button `Claim`
- Description `<amount> SOL to <n> members, published on <devnet|mainnet>. Use the wallet you verified with the bot; it signs and pays for its own claim.`
- A disabled card's description is the epoch page's existing sentence (`unavailableSentence`).

POST success message:
- `Claim <amount> SOL from <community>, epoch <n>. Your wallet pays the network fee and the claim receipt's rent.`

Errors:
- `This is not a Hyphae claim link.`
- `Connect a Solana wallet to claim.`
- `This epoch does not exist.`
- `Hyphae can't be read right now. Try again in a minute.`
- `This wallet has no payout in epoch <n>. Use the wallet you verified with the bot.`
- `This wallet already claimed epoch <n>.`
- `This claim can't be checked right now, so nothing was built. Try again in a minute.`
- Not published, or the chain cannot confirm: the existing `unavailableSentence` text.

## What the release needs

1. **Codex review** of this branch's diff (wallet and transaction code), findings fixed test-first.
2. **Merge and deploy after the hold** (no push or deploy before 2026-10-10T00:00Z). It ships with the normal Vercel build of `main`. No API deploy, migration, secret or environment change.
3. **Registry decision (Cisco):** X shows a link as a blink only if it is registered with a blink registry (Dialect's today). Registering is an external action and Cisco's call; this work does not register anything. Unregistered, the shared link shows the claim page's normal link card and opens the claim page. Wallets and sites that read `actions.json` can still find the Action.
4. **Approve the strings above.** The X composer opens with the link only and no prefilled text. Any text would be public wording for Cisco to set.

## Test with a real wallet on devnet first

1. Use a devnet community with a published epoch that has a leaf for your test wallet (the [devnet run](https://github.com/FCisco95/hyphae-program#a-full-run-on-devnet) shows how to get one), served by an API that reads it.
2. Deploy this branch as a Vercel preview with `HYPHAE_API_URL` pointing at that API (preview environment only). Turn off Deployment Protection for that preview, or a blink client cannot fetch it.
3. Check the routes with curl: `curl -i -X OPTIONS <preview>/api/actions/claim/<mint>/<n>` (204 and the CORS headers), `curl -s <preview>/actions.json`, `curl -s <preview>/api/actions/claim/<mint>/<n>`, then `curl -s -X POST -H 'content-type: application/json' -d '{"account":"<test wallet>"}' <preview>/api/actions/claim/<mint>/<n>`.
4. Set Phantom (or Solflare) to devnet. Open the Action in a blink client in devnet mode, for example `https://dial.to/?action=solana-action:<URL-encoded Action URL>&cluster=devnet`. This uses a third-party viewer for a test only; nothing is registered. Press Claim and sign.
5. The claim page for that epoch should then show the leaf as paid, with the transaction. A second POST should return 409 `This wallet already claimed epoch <n>.`
