## Fix check on `a4c5063..1185ad1`: ACCEPT

Codex's verdict: "ACCEPT", no new findings. The proof requires `output IS NULL` inside the existing community lock, so a stored response blocks it before any nomination or fence change; the late attach uses the same lock and requires `pending_reconciliation`, so if the proof wins first the attach cannot touch the row. Neither order produces `not_sent_proven` beside a stored response. The operator's error says a response is recorded and the request was sent. An Anthropic output kept after a schema failure blocks the proof too, which is correct: an invalid response still proves sending. Genuinely unsent dispatches keep their recovery, close, fencing and budget behavior. 192 rewards tests passed in its sandbox, including both new ones.
